# 物料收纳柜管理系统

一款面向电子工程师 / 实验室的**物料收纳柜管理桌面应用**，支持格位可视化、BOM 批量导入匹配、立创商城联网查价查库存、内置元件库沉淀等功能。

应用名称：物料收纳柜

***

## 一、系统简介

| 项目   | 说明                                                                |
| ---- | ----------------------------------------------------------------- |
| 运行方式 | 桌面窗口（pywebview 容器 + 本地 HTTP 服务），窗口尺寸 1440×900，支持 DPI 自适应          |
| 柜体规格 | **5 行（A–E）× 8 列（1–8）= 40 个大格**，每大格分「前 / 后」两小仓，共 **80 小格**，全部为正常仓位 |
| 格位编码 | 界面标签：左=前仓、右=后仓；数据库编码保留 `A1-内`、`A1-外` …… `E8-外`（不迁移）               |
| 数据存储 | 本地 SQLite（`inventory.db`），首次启动自动建库建表，无需配置数据库服务                    |
| 首次启动 | 干净空库：仅含 80 个格位与默认设置，**无任何演示数据**                                   |
| 操作日志 | 自动记录入库 / 出库 / 编辑 / BOM 等操作（时间 / 操作类型 / 目标 / 详情），**不记录操作者**        |
| 应用图标 | 网页详细信息页与 Windows EXE 统一使用 `app_icon.ico`，旧图标资源已移除                 |
| 联网能力 | 立创商城（LCSC）公开接口自动匹配，**无需配置任何密钥**；GitHub Release 更新与脱敏库存同步为可选功能     |

***

## 二、快速开始

### 环境要求

- Python 3.8 及以上

- Windows 10/11（macOS / Linux 理论可用，未深度测试）

- 依赖包：`pywebview`、`openpyxl`

### 安装依赖

```bash
pip install pywebview openpyxl
```

### 启动程序

```bash
python main.py
```

启动后自动打开桌面窗口，并完成：

1. 初始化本地数据库（含 80 个格位记录）
2. 启动本地静态资源服务（127.0.0.1 随机端口）
3. 注入桥接脚本，前端 `api.*` 调用直达 Python 业务层

## 三、功能与页面说明

### 1. 格位总览

- 5×8 柜体矩阵可视化，每格显示前 / 后仓占用状态（左=前仓，右=后仓）

- 格位网格固定 **8 列 × 5 行** 展示，窗口拉伸时随宽度自动缩放，列数保持不变

- 状态颜色：已占用（蓝）、空闲（灰）、**低库存（淡红）**，概览图例同步标注

- 点击格位查看物料详情、入库、出库、移库

### 2. 物料管理

- 新建 / 编辑 / 删除物料，字段包括：物料编码、名称、规格（参数）、封装、分类、供应商编号、立创编号、库存上下限等

- **正式新增弹窗**：列表页「新增物料」打开结构化弹窗（编码 / 名称 / 供应商编号 / 立创编号 / 规格 / 封装 / 分类 / 最低库存 / 参数 JSON），保存后自动调用仓位推荐并提示建议格位

- **行内编辑**：每行「编辑」按钮复用同一弹窗回填全部字段，参数对象自动格式化为 JSON 展示

- **顶部入口全局可用**：右上角「新增物料」在任意页面点击后跳转物料页并自动弹出新增弹窗

- **列表完整展示**：表格列已精简合并（「名称/型号」合一、规格作辅助行），关键列宽度受限，1440 窗口下全部列完整可见，多格位物料悬停可看完整位置

- 支持关键字搜索、按分类筛选

- 库存预警：低于下限自动提示

### 3. BOM 导入与领料（重点页面）

页面顶部为「导入 BOM」按钮 + 操作类型切换（**补货入库 / 领料出库**），下方为物料清单表格。

**本次更新亮点：**

- **多文件批量导入并合并**：点击选择文件可多选，或一次拖入多个 BOM 文件（`.csv` / `.xlsx` / `.xls`），全部解析后**合并到同一清单**统一展示与匹配；之后再次导入新文件，**继续追加合并**到当前清单（领料/补货类型需一致，不同模式自动新建清单）

- **列表滚动浏览**：物料较多时清单区域内部滚动，**表头吸顶**，不会把页面撑长

- **底部操作栏常驻**：「匹配物料」「执行入库/出库」等三个按键固定在页面底部，滚动列表时始终可见可点

- **操作类型记忆**：切换到其他页面再回来，操作类型保留上次选择

- **列信息整合**：领料表格 8 列（勾选/行号/物料名称编码/Supplier Part/需求数量/匹配状态/所在格位/缺口），补货表格 9 列（勾选/行号/物料名称编码/Supplier Part/需求数量/待补数量/推荐存放格位/补货数量/匹配说明）；名称列整合 `Comment` 主名 + 编码辅助行 + 规格·封装辅助行，避免列过多导致横向溢出错位

- **名称显示规则**：列表主名称优先显示 `Comment`，次选物料名称/编码；匹配时优先以 `Supplier Part` 为准

- **融合匹配**：匹配时多路并发（立创供应商编号 → 本地参数 → 内置记忆库 → API 兜底），显著缩短匹配等待

- **领料可视化**：确认领料后自动跳转概览，对应仓格显示需求数（绿=可正常取料，红=缺料）；**点击取料仓标记已取料（白底黑字），全部取完自动退出取料状态回到总概览**

- **补货可视化**：确认补货入库后同样跳转概览，对应仓格显示需放入物料的**供应商编号**，点击标记已放入、全部完成自动退出

- **概览标题自动切换**：取料时显示「收纳柜取料概览」，补货时显示「收纳柜补货概览」，平时为「收纳柜占用概览」

- **流程步骤条**：上传 BOM → 解析匹配 → 库存核对 → 确认（当前步骤黑色、已完成绿色、后续灰色；第 4 步按模式显示「确认领料」或「确认补货」）；**「清空」后清单与流程一并回退到第一步**，空态提示恢复正常引导文案

- **合并确认按钮**：领料 BOM 显示「确认领料」，补货 BOM 自动切换为「确认补货入库」，一钮通用

- **导入即匹配**：领料模式导入 BOM 后自动执行库存匹配，确认领料直接可用，无需先手动点「匹配库存」

- **勾选处理**：清单每行左侧可勾选，左下角「全选」一键全选，**导入 BOM 后默认全选全部行**；确认领料/补货只处理已勾选行，操作完成后自动从清单移除（全选+确认等价整体清空）

- **补货自动推荐**：补货清单自动匹配推荐存放格位（第二次及后续导入同样生效），同一批物料按空格顺序相邻排布

- **步骤自动推进**：导入完成自动进入第二步，匹配结束自动进入第三步；确认补货**全部成功进入第四步并跳转概览**，仅当存在失败行时**停留第三步**等待重新「匹配库存」

- **类型切换重匹配**：导入 BOM 后更改操作类型，自动回退到第一步、清空旧类型匹配结果，并按新操作类型重新匹配与推荐仓位

- **切换类型不错位**：领料/补货表头与数据列严格对齐（列宽受控、表头可换行），切换操作类型只渲染目标模式，不再出现下方列错位/偏移

- **顶部入口全局可用**：右上角「导入BOM」在任意页面点击后跳转 BOM 页，并自动触发「选择 BOM 文件」；右上角「新增物料」跳转物料页并视为点击了「新增物料」，自动弹出编辑弹窗（填写参数、自动匹配并推荐存放位置）

- **切换页面不重载**：导入并匹配 BOM 后切到其他页面再返回，自动恢复上次清单与流程步骤，**不重新加载、不重新联网匹配**（无操作时零等待；需要更新可手动点「库存匹配」）

**解析健壮性（v1.15.7 修复）：**

- **表头识别列独占**：列名匹配改为「精确优先 + 一列只归一个字段」，`规格` / `规格型号` 这类互为子串的列名不再互相抢占（此前 `规格` 会被误当成物料编码列，导致同规格、不同供应商编号的两行被错误合并——73 行 BOM 只识别 71 行的根因）

- **多工作表自动选表**：Excel 导入自动在全部工作表中选「表头命中数最高」的一张作为数据表，彩色封面 / 「说明」页被设为活动表时不再导致解析为空

- **多备选编号逐个匹配**：一格多个供应商编号（逗号 / 分号 / 斜杠 / 顿号分隔）会拆成编号集合，与库存、记忆库逐编号求交集

- **历史拼接编码兼容**：数据库中已存在的「逗号拼接编码」物料（如 `C21190,C2907002`）自动兼容——完整编号搜索、BOM 编号匹配、编码精确查询均可命中，不再出现「输入完整供应商编号反而搜不到」

- **兜底建档去污染**：BOM 行自动建档时 `material_code` 只取首个编号，不再产生新的逗号拼接编码

### 4. 立创联网搜索（自动集成，无需配置）

- 匹配过程自动联网查询立创商城公开接口（`wmsc.lcsc.com`），**无需注册、无需配置任何密钥**（设置页已移除密钥配置栏目）

- 物料详情 / 匹配结果页仍可一键手动联网搜索，返回型号、品牌、封装、参数、现货、单价

- **确认选中某条联网结果后，系统自动把该物料的供应商编号与参数写入内置元件库**，下次优先命中，不再联网

### 5. 内置元件库（历史库存记忆库）

- 表：`component_library`，记录 `立创编号`、`供应商编号`、`型号`、`名称`、`规格参数`、`封装`、`品牌`、`分类`、`参数 JSON`、`命中次数`

- 沉淀来源：① 立创搜索确认；② BOM 匹配后补货入库确认

- **独立管理页面**：设置页顶部选项栏最右侧「历史库存记忆库」独立入口打开专属页面（不再占用物料页分类，也不在能力入口网格内），支持关键字搜索

- **完整维护能力**：单行勾选、表头全选、单条编辑（结构化表单，参数 JSON 自动格式化）、单条删除、**按勾选批量删除**（删除失败条数会明确提示）

- 收益：**越用越快、越用越准** —— 常用物料离线秒匹配，减少联网等待与接口压力

### 6. GitHub 版本与库存同步

- 设置页可配置私有仓库 `LCZ-195/material-cabinet`、GitHub Token 和启动检查开关。

- Token 仅保存到当前 Windows 用户的 `%LOCALAPPDATA%\\物料收纳柜\\github_token.bin`，使用 Windows DPAPI 保护，不写入数据库、源码、EXE 或 GitHub 快照。

- 版本更新只接受 GitHub Release 中的 EXE，并要求 Release 附带 `SHA256.txt`、`checksums.txt` 或 `checksums.sha256`，清单中必须存在对应 EXE 文件名和 64 位 SHA-256；校验失败会拒绝替换。

- 更新采用临时下载文件和独立替换进程，主程序退出后才替换当前 EXE。

- 库存同步只上传 `materials` 与 `inventories` 的白名单字段，使用稳定的格位编码，不上传 `app_settings`、日志、BOM 路径或 API 密钥；远端记录按 `update_time` 合并。

- 启动自动检查失败不会阻止程序运行；私有仓库的版本下载与库存下载、上传都需要在设置页配置 Token。

- 发布流程：构建 `物料收纳柜.exe`，计算 SHA-256，创建 GitHub Release（tag 使用版本号，如 `v1.15.7`），以 ASCII 资产名上传（如 `material-cabinet-v1.15.7.exe`，避免 Unicode 资产名经 API 上传时被改名为 `default.exe`），同时上传与 EXE 资产名逐字一致的 `SHA256.txt`。

### 7. 数据管理（设置页）

- **清除演示数据**：一键清空全部业务表（物料 / 库存 / 操作日志 / BOM 记录），保留 80 个格位、设置与内置元件库

- 系统设置：AI 匹配（DeepSeek）、默认最低库存、同参数合并放格、补货自动推荐等开关

- **独立系统设置入口**：设置页顶部选项栏（连接与规则 / 数据与安全 / 能力入口）最右侧新增「历史库存记忆库」独立入口，点击直达记忆库维护页（不再混在能力入口网格内）

## 四、物料匹配方式（核心机制）

### 融合匹配四路并发流程

匹配时对**每一行 BOM 同时启动**三路独立匹配，谁先命中按优先级取用，全部未中再走 API 兜底——避免"先本地、后联网"的串行等待：

```
BOM 行
  │  并发启动（ThreadPoolExecutor，本地/联网并行）
  ├─ ① 立创供应商编号匹配（联网，最高优先）
  │      立创编号(Cxxxx)查详情 / 厂商型号(Supplier Part)搜索
  │      命中后 → 沉淀内置记忆库 → 回查本地库存
  │
  ├─ ② 参数匹配（本地，秒回）
  │      供应商编号精确 → 编码精确/模糊 → 规格+封装 → 名称 → OR 兜底
  │
  ├─ ③ 本地记忆库匹配（内置元件库，离线秒回）
  │      供应商编号精确 → 立创编号精确 → 关键词 → 规格+封装
  │
  └─ ④ ①-③ 均未命中 → API 关键词搜索兜底
         按 规格+封装 过滤候选 → 命中自动沉淀回内置记忆库
```

> 三路并发后：单行匹配耗时 ≈ max(联网耗时, 本地耗时)，而非 串行相加；无供应商编号的行①直接跳过不联网，进一步提速。

### 匹配优先级细则（BOM 行字段如何使用）

| 优先级 | 字段              | 说明                                                       |
| --- | --------------- | -------------------------------------------------------- |
| 1   | `Supplier Part` | **首要匹配键**。若填的是立创编号（C 开头数字），直接查详情；若是厂商型号，先查本地库存/记忆库，再联网搜索 |
| 2   | `Comment`       | 描述/参数匹配。与库存物料的「规格（参数）」做相似度比较；**封装不同但参数相同视为可合并**          |
| 3   | 物料编码 / 名称       | 传统主键匹配                                                   |
| 4   | 规格 + 封装         | 组合匹配                                                     |
| 5   | OR 兜底           | 任意字段部分命中即给出候选，标记为 `partial` 待人工确认                        |

### BOM 表列填写建议

为了让匹配又快又准，推荐 BOM 中保留以下列（列名不区分大小写、自动识别常见别名）：

| 推荐列名            | 别名示例                       | 用途                            |
| --------------- | -------------------------- | ----------------------------- |
| `Supplier Part` | Supplier Part No.、MPN、厂商编号 | **最重要**，填厂商完整型号或立创编号          |
| `Comment`       | Description、Value、备注       | 元件值/描述，如 `100nF 50V X7R 0402` |
| `Footprint`     | Package、封装                 | 如 `0402`、`SOT-23`             |
| `Quantity`      | Qty、数量                     | 需求量                           |
| `Reference`     | Designator、位号              | 位号（合并同类项用）                    |

> 💡 **最佳实践**：从立创商城导出 BOM 或在原理图属性里填好 `Supplier Part` 列，一次投入终身受益 —— 后续每次导入都直接命中内置库，无需联网。

## 五、存放位置推荐规则

自动分配建议格位按以下优先级（**A–E 全部 80 格均参与**）：

1. **参数相同同格合并**：已有相同「规格（参数）」的物料所在格位优先 —— 即使封装不同（如 0402 与 0602 的 100nF），也允许放一起，便于按值取料
2. **同分类 + 同封装归堆**：把同大类、同封装的物料集中在相近格位
3. **空格位从 A1 排起**：**贴片类（电容电阻等）从最小封装开始排、同封装排完再排下一组**（0402 → 0603 → 0805 → …）；**插件类（DIP/TO 等）在贴片排完后再排**；同一批互不重复

> 空格位从 **A1 排起、按 A1→E8 顺序连续填充**；E 行（E1–E8）为正常仓位，与其他行同等参与自动分配。

## 七、常见问题

**Q1：导入 BOM 后很多「未匹配」怎么办？**
A：检查 `Supplier Part` 列是否填写完整；点击未匹配行的「联网搜索」，在候选中确认一条 —— 确认后自动沉淀进内置库，下次同款秒匹配。

**Q2：自动建议会推荐 E 行吗？**
A：会。E 行（E1–E8）已改为正常仓位，与 A–D 行同等参与自动分配与推荐。

**Q3：封装不同、参数相同的两个电容会分开放吗？**
A：不会。推荐算法第 1 优先级就是「参数相同同格合并」，封装差异不影响合并，方便按值取料。

**Q4：一次能导入多个 BOM 文件吗？**
A：可以。点击「导入 BOM」按住 Ctrl 多选，或直接把多个文件一起拖入上传区，系统逐个解析后汇总显示。

**Q5：数据存在哪里？如何备份？**
A：全部在项目根目录的 `inventory.db`（SQLite 单文件），复制该文件即可完成备份。

**Q6：联网搜索需要配置 API 密钥吗？**
A：不需要。当前使用立创商城公开搜索接口，无需注册；若接口变更，可在 `config.py` 中切换为官方开放平台密钥模式。
